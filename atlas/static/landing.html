01The premise

A chat box
is not
an analyst.

Most AI analytics stops at a plausible sentence. It guesses the column, hides the query, and hopes the number is close enough.

Atlas starts with the row. It profiles before it answers, validates every query against a read-only policy, and refuses to put a number in a sentence unless that number came back from the database.

02The method

Every answer has
a paper trail.

A deterministic engine builds the plan. A guard checks it. DuckDB runs it read-only. The narrator writes only from the rows that came back.

SQL policy · live
SELECT plan,
       SUM(revenue) AS value
FROM ds_saasrevenue
GROUP BY plan
ORDER BY value DESC;
✓one statement · read-only · 4 rows
blockedDROPATTACHCOPYread_csvPRAGMA

External access is disabled at the DuckDB level, not just hidden behind a regex. Uploads are capped, rows are capped, and long queries are interrupted.

  1. 01

    Read

    Resolve the intent, the columns, the filters and the grain. If the question is ambiguous, say so.

    ⌁
  2. 02

    Plan

    Build one explicit SELECT with a known shape. No free-form model guess, no hidden second query.

    ⌗
  3. 03

    Guard

    Reject writes, DDL, file access and multiple statements. Mask literals so a string cannot trip the scanner.

    ⊘
  4. 04

    Run

    Execute read-only with a row limit and a watchdog. Return the columns, the rows, the SQL and the time.

    ▷
  5. 05

    Ground

    Write the narrative from the returned values. An optional model can polish the prose, but any number it invents is rejected.

    ≈

05The promise

No black boxes.

No invented numbers.

No data leaving.

01

Read-only by construction

DuckDB opens with external access disabled. The guard rejects writes, DDL, file functions and multiple statements. A watchdog interrupts anything slow.

02

Grounded by construction

The narrator emits a facts dictionary. Optional model prose is rejected if it introduces a number that is not in those facts. The answer is checked, not trusted.

03

Local by default

One process, one DuckDB file, zero telemetry. Connect a model only if you choose to, and only as a narrow planner or prose polisher — never as the source of truth.
